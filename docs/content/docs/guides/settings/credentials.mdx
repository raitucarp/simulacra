**Credentials** in Settings › AI & Models is the key ring of the app. The provider pane above it sets the one default service; here you keep every other key an agent, an embedding model or an image engine may need.

<Screenshot id="settings-credentials-list" alt="The CREDENTIALS card: the note, a Local engine credential (Custom Endpoint with a masked key and its address) and a Personal OpenAI key, each with edit and remove icons, and Add credential in the header" caption="Settings › AI & Models › CREDENTIALS." size="md" />

## Anatomy

- **Header.** <UiLabel>CREDENTIALS</UiLabel> and <UiLabel>Add credential</UiLabel>.
- **Note.** <UiLabel>Keys for every provider and service your agents use. Agents pick a credential by name; keys stay in this local vault and are only sent to their own service.</UiLabel>
- **One row per credential**, in the order you added them: its name, then the service and the masked key (`Google Gemini · ••••a1b2`), and its endpoint when it has one. The pencil (<UiLabel>Edit</UiLabel>) opens the form on it; the bin (<UiLabel>Remove</UiLabel>) deletes it at once.
- **Empty state.** With nothing stored: <UiLabel>No credentials yet. The global provider above is used by every agent.</UiLabel>

## Services

| Service chip | Used for |
|---|---|
| Google Gemini, OpenAI, Anthropic, OpenRouter, Groq | Text models of that provider. Google Gemini and OpenAI keys also serve embeddings and the image engines of the same name. |
| Custom Endpoint | An OpenAI-compatible service; put its address in <UiLabel>Endpoint (optional)</UiLabel>. Also used by the **Custom** embedding provider. |
| Brave Search, Tavily | The web search tool of agents. |
| HTTP | A bearer token for custom HTTP tools, custom requests or local image servers. |

## Add a credential

<Steps>
<Step>
### Open the form

In Settings › AI & Models, click <UiLabel>Add credential</UiLabel>. The form opens under the list.
</Step>
<Step>
### Pick the service

Click one of the nine service chips. The chosen one is filled.
</Step>
<Step>
### Name it and paste the key

Give it a <UiLabel>Name</UiLabel> agents will recognise (<UiLabel>e.g. Personal OpenAI key</UiLabel>); a blank name becomes the service's name. Paste the key into <UiLabel>API key</UiLabel> (empty, it reads <UiLabel>Paste the API key</UiLabel>). The key shows as dots; the eye button at the end of the field shows it while you check it.
</Step>
<Step>
### Override the address (optional)

<UiLabel>Endpoint (optional)</UiLabel> replaces the service's base URL, for example `http://localhost:8000/v1/chat/completions`.
</Step>
<Step>
### Save

Click <UiLabel>Save credential</UiLabel>. It is stored at once, and agents that were backing off after failures try again with it. <UiLabel>Cancel</UiLabel> closes the form without saving, and so does closing Settings.
</Step>
</Steps>

<Screenshot id="settings-credentials-editor" alt="The credential form: nine service chips with OpenAI chosen, Name, API key and Endpoint fields, Cancel and Save credential" caption="Adding a credential." size="md" />

To change a credential, click its pencil. The key field starts empty and says <UiLabel>Leave blank to keep the stored key</UiLabel>: leave it blank to change only the name, service or endpoint.

## The Main AI key credential

The key you save in the provider pane is mirrored into a credential named <UiLabel>Main AI key</UiLabel> (in the interface language, until you rename it). It appears once the provider pane holds a key and follows every later save there. Editing <UiLabel>Main AI key</UiLabel> in this list edits the provider pane too: its service becomes the provider (with that provider's default model when the provider changes), and its key and endpoint become the provider's.

## Which key is used

| Who asks | Which credential it gets |
|---|---|
| An agent | The credential its engine names. When it names none, or the named one was removed, the first credential of the needed service that holds a key. See [Engines](/docs/guides/agents/engines). |
| Embeddings | The first credential of the embedding provider's service (Gemini, OpenAI or Custom). For Gemini, the provider pane's key when no Gemini credential holds one. |
| Image engines | The credential the image engine names; otherwise the first Google Gemini credential for Google and the first OpenAI credential for OpenAI. |

## How keys are protected

| | |
|---|---|
| **Where they are kept** | In your vault's settings table: the credentials as one stored row, the provider pane's key in its own row. Not in the operating system's keychain, and the vault file itself is not encrypted, so anyone who can read the file can read the keys. |
| **How they are shown** | Masked to their last four characters (`••••a1b2`); a key of eight characters or fewer shows only `••••`. The key fields draw what you type as dots until you press their eye button. The edit form never refills a stored key. |
| **Where they are sent** | Only to their own service, with the requests that need them. |
| **In messages** | Error messages and tool output have every stored key removed before they are shown or kept. |
| **In exports** | An [export bundle](/docs/guides/data/export) never contains credentials, API keys or provider settings, and secret-looking fields of agent configurations are written as `[redacted]`. |
| **In snapshots** | An [encrypted snapshot](/docs/guides/data/snapshots) holds the whole vault, keys included, sealed with your passphrase. |
| **In code runs** | Code blocks run with a cleared environment; no key reaches them. See [Code](/docs/guides/settings/code). |

## Tips and limits

- A key field hides what you type behind dots; its eye button shows it, for example to check a pasted key, and hides it again.
- Removing a credential asks no question. An agent that named it falls back to the first credential of its service.
- Resetting all settings keeps every credential. Only removing them here deletes them.
