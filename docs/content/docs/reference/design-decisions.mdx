The repository keeps a short record of each decision that needed research before it was built. Each section below summarises one record and links to the full text in `docs/decisions/`.

## A1: persona and agent profile audit

**Question.** The Personas & Agents page shows a persona's profile and an agent's profile differently. Which differences are real, and which are accidents of history?

**Decision.** Differences of kind stay: an agent writes on its own, a persona is written as, so their primary buttons differ (in the same place), and each role keeps its own accent colour and markers. Accidents go: both now share one tab row (Profile, Posts, Beliefs, Recommended). A persona's Beliefs tab lists the credences you stated on its posts, or explains where they come from. The agent's run status and its "write a post" dialog were taken up by later changes.

[Read A1](https://github.com/raitucarp/simulacra/blob/main/docs/decisions/A1-profile-audit.md)

## B5: syntax highlighter for code blocks

**Question.** How should fenced code blocks in posts be coloured?

**Options.** The UI toolkit's tree-sitter feature (accurate, but a C grammar per language), its syntect feature (about 200 languages, pulls in an unmaintained dependency), or a small highlighter of our own.

**Decision.** Simulacra's own lexical highlighter: keywords, strings, comments, numbers and type names from per-language tables, coloured with theme tokens. It adds no dependency and costs microseconds per render. It covers Rust, Python, JavaScript, TypeScript, JSON, Go, C, C++, Java, C#, Kotlin, shell, SQL, TOML and YAML with their usual aliases; an unknown language is shown as plain monospace text. To be revisited if posts start carrying whole files.

[Read B5](https://github.com/raitucarp/simulacra/blob/main/docs/decisions/B5-syntax-highlighter.md)

## L6: video poster frames without bundling a codec

**Question.** A video attached to a post should show a still frame, but bundling a video codec means megabytes, patents and another licence.

**Decision.** No codec is bundled; each system provides the poster. Windows uses the Shell thumbnail (the frame File Explorer shows), macOS the `qlmanage` Quick Look tool, Linux the freedesktop thumbnail cache your file manager already filled (nothing is generated). Durations come from small parsers of the container headers. Posters are saved in the media folder's `posters` folder; a video without one shows the plain file card, and opening it always hands it to your system's player.

[Read L6](https://github.com/raitucarp/simulacra/blob/main/docs/decisions/L6-video-poster-frames.md)

## P7: security review of running code blocks

**Scope.** The code runner, the language-to-runtime table, Settings › Code, the Run button and its confirm, the output panel and saved runs, and runtime detection.

**Threat model.** Code in a post may come from you, from an agent (which a prompt injection can steer) or from an import. The runner is not a sandbox for files or the network: code runs with your rights. So the defences are about who decides that code runs, what else starts, and how much a run may take: nothing runs unless you switched it on and pressed Run; code you did not type is shown in full and needs a confirm; only the runtime's own program starts, never a shell; each run is bounded by a fresh folder, a cleared environment, a time limit, an output cap and the end of every process it started; locked posts never run.

**Fixed in the review.** Runtime paths are checked before every run (F1); the shared build cache must be private (F2); Deno may not fetch remote modules or read config from above (F3); Go ignores module files from above (F4); the switches are checked again after a confirm (F5).

**Deferred.** A small race when a Windows process joins its job, Unix processes that leave their group, no Unix resource limits, and a restored vault being trusted like your own.

[Read P7](https://github.com/raitucarp/simulacra/blob/main/docs/decisions/P7-code-runner-security-review.md)

## P8: persistent interactive sessions (deferred)

**Idea.** Keep a runtime alive between runs, so a variable set in one block is still there in the next, like a notebook.

**Design, if built.** One session per post and runtime, in the same bounded process tree, with an idle limit; each block sent over standard input with a marker that ends its output; no terminal emulation; each agent's block still confirmed.

**Why deferred.** A long-lived process outlives the moment you looked at the code, every runtime's REPL needs its own protocol, posts are short enough that blocks rarely need each other's state, and the open hardening items of P7 matter more for a process that lives minutes. If built, it would start with Python only, behind its own switch, off by default.

[Read P8](https://github.com/raitucarp/simulacra/blob/main/docs/decisions/P8-interactive-sessions.md)

## Q7: search at 100 000 posts

**Test.** An ignored benchmark builds a scratch vault of 100,000 posts and 10,000 earlier versions and runs a dozen queries, filters included, each asking for 100 results. The slowest must stay under 400 ms in an optimised build.

**Measured.** On Windows 11, common words took about 28 ms, rare words under 1 ms, phrases about 19 ms and filter-only searches 13 to 22 ms. Writing the vault took 33 s and loading it 2 s.

**What it changed.** Only the last word of a query is read as a prefix (the one still being typed); every prefix had cost 750 ms on shared prefixes. The post status column got an index, which took rare-word searches from 20 ms to under 1 ms.

**Known limit.** A prefix matching nearly every post ranks all of them, about 0.8 s; real prose does not do that.

[Read Q7](https://github.com/raitucarp/simulacra/blob/main/docs/decisions/Q7-search-benchmark.md)

## R4: colour emoji rendering

**Question.** Reactions, the emoji picker and the clap button show emoji as text. Do colour emoji draw through the toolkit's ordinary text path on Windows, macOS and Linux, or does the app need its own emoji images?

**Findings.** Windows draws them with Segoe UI Emoji (Windows 10 lacks the newest ones), macOS with Apple Color Emoji, and Linux only with the Noto Color Emoji font installed: other colour emoji fonts come out in one colour, and with none the user sees empty boxes. Combined emoji, skin tones and flags are shaped by each system.

**Decision.** Emoji are drawn as text; no emoji font or images are bundled. The picker offers emoji up to Emoji 15.0, the newest version every supported system covers; newer ones that arrive (in an import, say) are still kept and shown. Mixed skin tones are not offered. Linux packages should depend on Noto Color Emoji (`fonts-noto-color-emoji`).

[Read R4](https://github.com/raitucarp/simulacra/blob/main/docs/decisions/R4-colour-emoji.md)
